## 2. Метод: «регресс-безопасный» перенос по функциям

Для каждого файла, затронутого V5 (сначала мелкие и новые, `main.gd`/`menu.gd` — в конце):

1. **Нормализуй** три версии (V4, V5, наша): убрать комментарии/пустые строки, свернуть пробелы. Постройте индекс
   `func/const/var/signal` → хэш тела. `main.gd` (~8,5 тыс. строк у нас) и `menu.gd` (~6,3 тыс.) **целиком не читай** — только по индексу.
2. **Классифицируй каждый символ:**
   - `V5 == V4` → V5 его не трогала, **пропустить** (наши правки остаются).
   - `V5 ≠ V4`, `наш == V4` → **чистая дельта**: переносим тело V5 (с учётом переименований/расположения, см. п. 4).
   - `V5 ≠ V4`, `наш ≠ V4` → **конфликт**: трёхсторонняя ручная склейка. Поведение/содержание/баланс/тексты — из V5,
     способ исполнения (lite, потоки, `scripts/ui/*`, prebuilt-вкладки, navgrid, `_pl_*`, `perf_log`, завеса, атомарная подмена биома) — наш.
     Для каждого конфликта запиши в журнал: что взято у V5, что сохранено у нас, и **какой нашей правке это не должно навредить** (№ из таблицы).
   - символ только в V5 → новый, переносим (после оценки стоимости на A53).
   - символ только у нас → не трогаем.
3. **Антирегресс-проверка после каждого файла:** `git diff portmaster -- <файл>` не должен удалять строки нашего кода, кроме тех,

4. **Код V5 в `main.gd`, относящийся к HUD/карточкам/миникарте/слотам/команде,** переноси в наши `scripts/ui/hud.gd, cards.gd,

## 5.0. Бюджет лимитов (жёстко)

Окно: 5-часовое — **закончить работу к ≤90 %**, недельное — **к ≤98 %**. Если не укладываешься, останавливайся раньше и пиши остаток в handoff.
- Перед стартом и после каждого этапа проверяй расход (`mcp__ccd_session_mgmt__get_usage`). **≥70 % окна** → закончить текущий коммит, обновить
  handoff, начать только мелкие шаги; **≥85 %** → только коммит, handoff и остановка с рекомендациями; не начинай этап, который не успеешь закрыть.
  Недельный ≥90 % → остановиться после текущего этапа и сообщить владельцу.
- Основная сессия — по умолчанию (не max effort, не «ultra»); конфликтные склейки и дизайн — тут. Всё механическое — **дешёвым** субагентам:
  `model: "haiku"` — индексы функций/хэши, сбор ключей локализации, подсчёты, перенос чистых дельт без конфликтов по готовой таблице;
  `sonnet` — перевод строк, чтение незнакомого модуля с отчётом ≤40 строк. Opus/fable-субагенты — не использовать. ≤3 одновременно, fresh,
  без повторных запусков; неполный ответ — доспроси через SendMessage.
- Детерминированное делай скриптами (python/jq/grep), а не LLM: нормализация, хэши, diff индексов, проверка ключей `lang_*`.
- Не читай файлы целиком (особенно `main.gd`, `menu.gd`, `lang_*.json`, декомпилят); читай функции по индексу; логи — `tail/grep`.
  Тяжёлые прогоны (`mode_matrix`, `soak`, `bench_ab`) — по этапам в фоне, не «на всякий случай»; полную сетку (все стартеры × сиды × мета)
  — один раз в конце, на этапах — урезанную.
- Порядок этапов уже по ценности: если ресурс кончается, готовая часть (данные, слияния, исправления) должна быть работающей и закоммиченной,
  а недоделанное — в handoff, не в полусломанном состоянии (ветка должна проходить `check_all` на каждом коммите).
