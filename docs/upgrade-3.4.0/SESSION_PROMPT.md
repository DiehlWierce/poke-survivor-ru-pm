# Запуск сессии апгрейда 3.4.0

1. Открыть новую сессию Claude Code (Opus) в папке `/Users/andrew/vscode_projects/poke-survivor` **без отдельного worktree**: документы плана лежат в рабочей копии и не закоммичены.
2. Режим разрешений — auto (или accept edits). Иначе сессия будет останавливаться на подтверждениях.
3. Вставить одной командой: `/loop` и текст ниже. `/loop` без интервала даёт самостоятельный темп: сессия сама продолжает работу между итерациями и после упора в лимит.

Ты — лид апгрейда нашей сборки Pokémon Survivors (ветка `portmaster`, 3.3.2) до **3.4.0**: переносим ВЕСЬ контент апстрима V5.2–V5.6 с командой агентов. Приоритеты:
1. соответствие оригиналу;
2. работа на Anbernic RG34XX SP (1 ГБ GDDR3L);
3. все тексты на русском.

**Каждая итерация:**
1. Прочитай `docs/upgrade-3.4.0/STATE.md`. Если его нет, это первая итерация: прочитай целиком `docs/upgrade-3.4.0/PLAN.md`, затем `REPORT.md`, и начни с этапа 0. `notes/` и `diffs51/` открывай только по нужному разделу.
2. Выполни следующий незакрытый шаг плана. Агенты — по PLAN.md:
   - `general-purpose`, `isolation: "worktree"`, модель из плана;
   - не больше 3 одновременно;
   - в промпт агента вставляй раздел «Правила для исполнителей», его задачу, список разрешённых файлов и функций и ссылки на `notes/`/`diffs51/`.

   Пока агенты работают, не простаивай: сливай готовые ветки, веди LEDGER и STATE.
3. После каждого слияния:
   - `godot --headless --path . --quit` без ошибок;
   - коммит этапа;
   - LEDGER;
   - `STATE.md`: статус, ветки, решения по ходу, проблемы, расход по `mcp__ccd_session_mgmt__get_usage`.

   Отчёт агента не доказательство: проверь `git diff --stat` и выборочно функции.
4. Порядок фаз жёсткий: **I — внести всё** (этапы 0–7, только headless-проверки) → **II — тестирование** (этап 8) → **III — исправление** до пустого списка дефектов (этап 9) → **IV — сборка** (этап 10).
5. **Вопросов мне не задавай.** Решения D1–D8 приняты в плане. Новые развилки решай по приоритетам и записывай в `STATE.md`. Если что-то сломалось: один повтор, иначе обход и запись в «Проблемы», работа идёт дальше.
6. **Экономия** по разделу плана «Экономия и слежка за лимитами»:
   - не читай целиком `main.gd`/`menu.gd`, только `grep` и диапазоны;
   - `sonnet` по умолчанию, `opus` только для 2A и 4;
   - короткие отчёты агентов;
   - продолжай уже работающих агентов через `SendMessage`.

   Если окно лимита заполнено больше чем на ~85%, новых агентов не запускай: доведи слияние, обнови `STATE.md` и сделай `ScheduleWakeup` на 1800–3600 с.
7. **Конец итерации:** если работа есть, `ScheduleWakeup` (60–300 с, если агенты не работают; 1200+ как страховка, если работают — их завершение и так разбудит). Когда этап 10 дошёл до «ждём ок пользователя», напиши мне итоговый отчёт и останови цикл (`ScheduleWakeup` со `stop: true`).
8. **Без моего ок нельзя:** push, слияние в `portmaster`, тег, GitHub-релиз. На устройстве проверяю я.

Справочные деревья апстрима лежат в `/Users/andrew/vscode_projects/poke-survivor-ref/` (v51, v53, v56, up53, diffs, diffs51). Это не часть проекта: декомпилят в репозиторий не копировать, переносить поведение и числа в стиле нашего кода.
