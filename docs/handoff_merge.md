### R1: что нужно для детерминизма

`--seed N` в bench_frame.gd + `main.bench_seed_override` (вместо `randomize()`). Одного сида мало, остальные источники расхождения (все срабатывают только при `bench_seed_override >= 0`, игра без флага не меняется):

1. `_warm_terrain` (main.gd): лимит 2,2 мс на кадр определял, на каком кадре появится новый кусок мира (а значит, твёрдые предметы и столкновения). В режиме сида лимита нет.
2. `_update_enemies`: фаза «дальних» врагов `Actor.tick + get_instance_id() % 3`; id объектов Godot разные от запуска к запуску. В режиме сида фаза берётся из счётчика по порядку первого обращения (`Enemy.far_ph`).

Остальное (потоки запекания кусков, `Time.get_ticks_*` в бюджетах загрузки/травы, `q_auto`) на ход симуляции не влияет: проверено покадровым хешем позиций врагов (3596 кадров, 2 прогона, diff пуст).

Результат: 3 прогона `--scenario run --seed 12345` дают одинаковые kills=198 level=40 orbs=90 bullets=23 enemies=44, blank=0, vis_missing=0. Время кадра (не детерминировано): средн 2,51–2,58 мс, p99 6,65–7,99 мс (разброс средн ≈ ±1,5 %, p99 до ±10 %). Поэтому средн сравнивать можно с точностью ~2 %, p99 грубее.
