### R1: что нужно для детерминизма

`--seed N` в bench_frame.gd + `main.bench_seed_override` (вместо `randomize()`). Одного сида мало, остальные источники расхождения (все срабатывают только при `bench_seed_override >= 0`, игра без флага не меняется):

1. `_warm_terrain` (main.gd): лимит 2,2 мс на кадр определял, на каком кадре появится новый кусок мира (а значит, твёрдые предметы и столкновения). В режиме сида лимита нет.
2. `_update_enemies`: фаза «дальних» врагов `Actor.tick + get_instance_id() % 3`; id объектов Godot разные от запуска к запуску. В режиме сида фаза берётся из счётчика по порядку первого обращения (`Enemy.far_ph`).

Остальное (потоки запекания кусков, `Time.get_ticks_*` в бюджетах загрузки/травы, `q_auto`) на ход симуляции не влияет: проверено покадровым хешем позиций врагов (3596 кадров, 2 прогона, diff пуст).

Результат: 3 прогона `--scenario run --seed 12345` дают одинаковые kills=198 level=40 orbs=90 bullets=23 enemies=44, blank=0, vis_missing=0. Время кадра (не детерминировано): средн 2,51–2,58 мс, p99 6,65–7,99 мс (разброс средн ≈ ±1,5 %, p99 до ±10 %). Поэтому средн сравнивать можно с точностью ~2 %, p99 грубее.

### R3: плашка о сохранении (изменение поведения)

- `SV.save_blocked`: постоянная красная плашка под верхней панелью меню (без фокуса и без кнопок, focus trap модалок и управление геймпадом не затронуты): «¡Tu progreso no se guarda!», причина из `SV.last_save_error` (первая строка, ≤ 90 символов, текст технический, не переводится) и путь существующего сброса «Ajustes › Zona peligrosa › Borrar todo el progreso» (из существующих ключей). Нового сброса не добавлено.
- `recovered_from_backup` или предупреждение о поле: тост один раз за запуск.
- 5 новых ключей добавлены в 9 файлов data/lang_*.json (en, fr, it, pt_BR, pt_PT, ru, ja, zh_CN, zh_HK). Файла для `es` нет (исходный язык), `es_419` хранит только отличия, ключи не нужны. Существующие ключи не менялись.

### R4: прямой замер вместо полного забега

Микротест (scratch, 300 000 вызовов, 5 повторов) пути «удар» (12 чтений способности: Dictionary + `_abn()` против полей AbilityFx): 1,04–1,16 мкс против 0,48–0,51 мкс, экономия около 0,55 мкс на удар. При 10–20 ударах за кадр это 5–10 мкс из ~2500 мкс кадра (0,2–0,4 %), на A53 примерно ×40 то есть до ~0,4 мс из 33 мс (≈1 %). Это ниже разрешения бенча (средн ±2 %, p99 ±10 %), поэтому полный A/B ни подтвердить, ни опровергнуть выигрыш не может. Плюс: опечатка в имени поля ловится при разборе, а не молча даёт 0.0. Минус: `AbilityFx._init` через `set(k, …)` молча игнорирует новый ключ из данных, если поле не объявлено. Решение: R4 не применяется (измеримой пользы нет, риск тихой потери ключа есть). Код остаётся в e96b1e61.
