# Видимость способностей, эффектов и дропов (portmaster)

Жалоба: урон есть, а визуала способности (снаряд, молния, аура, зона) нет / мигает; пропадают частицы и орбы.
Правило владельца: ничего из визуала способностей и дропов не скрывать; лимиты только на косметику.

## Найденные причины (lite = приставка или `--keys-only`)
1. `pfx.gd`: перерисовка только в чётных кадрах + шаг 30 Гц с аккумулятором (`_lite_acc < 1/30`).
   При дрожании delta шаги ложились на нечётные кадры → длинные серии без `queue_redraw()`:
   лучи/молнии (жизнь 0.2 с), удары, кольца аур не рисовались или застывали; последний рисунок «висел».
   Измерено: эффекты рисовались лишь в ~40 % кадров своей жизни (в main — каждый кадр).
2. `pfx.gd`: `LITE_SPRITE_CAP = 64` на все спрайты: спрайты аур, ударов (claw/jaws/impact), бафов, рывка,
   попаданий луча/молнии и Z-ходов отбрасывались (до 23 % в насыщении).
3. `pfx.gd`: эффект, созданный в кадре с большим delta (рывок), старел раньше первого `_draw()` и умирал невидимым.
4. `main.gd _trim_fx`: лимит Fx (96 на приставке) считал ВСЕХ детей `fx` (орбы, снаряды, цифры) → при сотне орбов
   каждый новый Fx (луч опасности босса/столпа, вспышки травы) удалялся в кадре рождения (100 % обрезано).
5. `main.gd _spawn_orb`: слияние XP-орбов (>50 на земле) в «ближайший» из 48 последних — он мог быть за экраном,
   и дроп у убитого врага не появлялся (видимых дропов 27–67 %).

## Исправления
- pfx: перерисовка после каждого шага (порог шага 1/40 с, чтобы на 30 к/с не пропускать кадры);
  спрайты по умолчанию — визуал способности, тоже HARD_SPRITES=1000 (страховка); лимит lite (64) только для `o.cosm`
  (пузыри яда); частицы `force` до HARD_PARTS; новые спрайты/кольца/удары/лучи не стареют до первого шага (`nw`).
- main `_trim_fx`: считает только Fx (`active_fx`) и режет только косметические `burst`; лучи опасностей — никогда.
- main `_spawn_orb`: слияние только с орбом не дальше ORB_MERGE_R=36 px (дроп виден на месте смерти).
- Не тронуто (косметика, по правилу допустимо): бюджет мелких частиц 8/кадр и cap_parts lite 180 для обычных частиц,
  плотность 0.5 (меньше частиц во вспышке), слияние цифр урона, сон дальних орбов за экраном.

## Проверка
- `tools/vischeck.gd` (+ зонд `tools/vis_probe_pfx.gd`, подменяет скрипт pfx на лету): окно, lite, 30 к/с,
  бот бежит/возвращается/кружит/блуждает, насыщение (босс, толпа, орбы, предметы, 24 хода сразу, связка из 3),
  смена биома, вход в разлом; все 66 ходов прокачаны и эволюционированы; Z-ходы всех 18 типов по кругу.
- `tools/vischeck_suite.sh [OUT] [quick]` — режимы normal/daily/rush, стартеры 25/1/4/7/79, сейв fresh и max
  (временный HOME на прогон). Итог `SUITE_OK` нужен для приёмки. Полный набор ~15 мин на Mac.
- Перфоманс: `tools/bench_ab.sh --seed 7 HEAD~N 3`.

- Удешевление рисования (чтобы перерисовка каждый кадр не стоила кадра): `VFX.pc()` кэширует цвета палитры
  (был `Color.html()` на каждый пиксель удара/луча), в `_draw` pfx цвета с альфой и cos/sin считаются один раз
  на кольцо/удар/луч, кольца — инкрементальным поворотом. Рисунок pfx: 1.95 → 0.92 мс за перерисовку (бенч run).

## Цифры (Mac M4, lite, сид 7)
Видимость (vischeck, визуал способностей+Z на экране / дропы у убитых на экране):
| прогон | до: способности | до: дропы | после: способности | после: дропы |
|---|---|---|---|---|
| normal, Пикачу | 76.9 % | 26.9 % | 100 % (16 727) | 100 % (60) |
| daily | 73.8 % | 30.0 % | 100 % | 100 % |
| rush (только боссы) | 80.7 % | 32.0 % | 100 % | 100 % |
| normal, сейв max | — | — | 100 % (20 027) | 100 % (88) |
| стартеры 1/4/7/79 (корот.) | 70.8–81.0 % | 44–67 % | 100 % | 100 % |
До: Fx обрезано лимитом 100 % (в т.ч. лучи опасностей), pfx рисовался ~40 % кадров жизни эффекта.
После: обрезаны только косметические вспышки травы (burst), ghost-кадров 0, скрытых узлов 0.
Худшие фазы до: насыщение 76.8 %, бег вперёд 90.6 %. После — 100 % во всех фазах (бег, возврат, круги,
блуждание, насыщение с боссом, смена биома, разлом).

Перф `tools/bench_ab.sh --seed 7 30c40726 3` ×2 (6 пар, Mac сильно загружен, load avg 20–33):
avg после/до = 7.15 / 7.50 мс (−4.7 %), p99 = 28.98 / 27.82 мс (+4 %, в шуме: вторая серия 28.40/28.46, BENCH_AB_OK).
Без удешевления рисования было +16 % avg.

## Не проверено
- На самой приставке (muOS) не запускалось; perf_log недоступен (том не смонтирован).
- Частицы-«мелочь» (бюджет 8/кадр, cap 180) по-прежнему режутся: это косметика (искры попаданий, хвосты),
  vischeck показывает их отдельно (px:*), не в метрике 100 %.
