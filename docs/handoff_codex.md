## Проверка производительности

Для затрагивающих горячий путь шагов использовать `tools/bench_ab.sh <base-ref> [пары=3]`. Он сравнивает только изменённые `scripts/` файлы в том же worktree и с общим `.godot`, чередует порядок (нечётные пары: после/до; чётные: до/после), запускает каждый Godot через `/private/tmp/poke-bench-lock.sh codex` и восстанавливает рабочие файлы при любом выходе. Минимум 3 пары; при пограничном или шумном результате — до 5–6. Gate по средним пар: avg после ≤ до × 1.03, p99 после ≤ до × 1.05; во всех прогонах `bench_blank_frames=0`, `vis_missing=0`; PG hashes `3914984115/2461697248`. Если разница связана только со случайным числом снарядов, проверять `--prof`, добавлять пары и сравнивать время без секции «снаряды». Для изменений вне горячего пути бенч не нужен. Bench run недетерминирован: `main._ready()` вызывает `randomize()` и выбирает случайные мир/покемона, поэтому парные результаты имеют высокий разброс.

## Для merge-сессии

- После B5 показать игроку `SV.save_blocked` и `SV.last_save_error` в `menu.gd`; файл `menu.gd` здесь не меняю.
- Для A5 вынести числа в именованные `const` в `_enemy_step`, `_update_bullets` и spawn внутри `main.gd`, сохранив текущие значения.
- Для A7 проверить сохранённые ссылки `target`, `_tower`, `partner` в `main.gd` и добавлять `is_instance_valid`/null guards там, где ссылка может пережить `queue_free`.
- Для детерминированного бенча нужна правка в запрещённом `main.gd`: объявить `static var bench_seed_override := -1`; в `_ready()` заменить безусловный `randomize()` на `if bench_seed_override >= 0: seed(bench_seed_override) else: randomize()`. В `bench_frame.gd` загрузить `res://scripts/main.gd` как GDScript и до `root.add_child(m)` установить `MAIN_SCRIPT.bench_seed_override = SEED`. Тогда seed применяется в начале `_ready`, прежде чем `_boot_data` выберет покемона/мир и создаст случайный cast. Измеренный вариант с `seed()` после `_ready` не воспроизводит XP/kills.
- Если потребуется изменение запрещённых `main.gd`/`menu.gd`, оставить здесь точные инструкции для merge-сессии.

## Риски и не проверено

- Свежесть удалённого `origin/portmaster` не подтверждалась в предыдущей сессии; worktree основан на локальном ref `bde672c8`.
- Базовые и текущие бенч-результаты получены на Mac; производительность на Cortex-A53 отдельно не проверена.
- Bench run случайный и результаты даже при общем замке сильно гуляют; это может маскировать небольшие изменения горячего пути.
- CA lookup `ERROR` — известная диагностика Godot/macOS исходной среды. Сейчас `check_all.sh` исключает только эту точную строку и известное сообщение о ресурсах; прочие `ERROR`, `Parse Error` и `SCRIPT ERROR` приводят к ошибке.
