## Проверка производительности

Для затрагивающих горячий путь шагов использовать `tools/bench_ab.sh <base-ref> [пары=3]`. Он сравнивает только изменённые `scripts/` файлы в том же worktree и с общим `.godot`, чередует порядок, запускает каждый Godot через `/private/tmp/poke-bench-lock.sh codex`, восстанавливает рабочие файлы при любом выходе и сверяет средние avg/p99, `bench_blank_frames` и `vis_missing`. Gate: avg после ≤ до × 1.03, p99 после ≤ до × 1.05, blank=0, vis_missing=0. Для изменений без горячего пути бенч не нужен.

## Для merge-сессии

- После B5 показать игроку `SV.save_blocked` и `SV.last_save_error` в `menu.gd`; файл `menu.gd` здесь не меняю.
- Для детерминированного бенча нужна правка в запрещённом `main.gd`: объявить `static var bench_seed_override := -1`; в `_ready()` заменить безусловный `randomize()` на `if bench_seed_override >= 0: seed(bench_seed_override) else: randomize()`. В `bench_frame.gd` загрузить `res://scripts/main.gd` как GDScript и до `root.add_child(m)` установить `MAIN_SCRIPT.bench_seed_override = SEED`. Тогда seed применяется в начале `_ready`, прежде чем `_boot_data` выберет покемона/мир и создаст случайный cast. Измеренный вариант с `seed()` после `_ready` не воспроизводит XP/kills.
- Если потребуется изменение запрещённых `main.gd`/`menu.gd`, оставить здесь точные инструкции для merge-сессии.
